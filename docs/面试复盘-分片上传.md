# 分布式智能网盘：面试复盘

> 使用方式：先脱离答案口述每题，再对照“更好回答”补齐遗漏。回答要紧扣当前项目实现，不要把未实现的能力说成已实现。

## 题目 1：2 GB 文件的完整上传链路

### 面试问题

用户上传一个 2 GB 文件，从前端点击上传到文件可在列表中下载，完整链路如何流转？请说明：前端切片、秒传、断点续传、分片记录、合并、存储和异常恢复。

### 本轮回答要点

- 前端以约 4 MB 为单位切片。
- 前端通过文件流将分片传给后端。
- 前端为文件计算 MD5，并希望为每个分片计算 MD5。
- `identifier` 用于标识文件，`userId` 用于用户隐私隔离。
- 认为最后一个分片上传成功后由后端自动合并，但对具体机制不确定。

### 面试官纠偏

1. 切片发生在前端，后端接收的是每个 `multipart/form-data` 分片请求。
2. 当前项目的 `identifier` 是**整文件 MD5**，不是每个分片的唯一标识；单个分片应由 `userId + identifier + chunkNumber` 定位。
3. 当前接口没有分片 MD5 字段，不要说“已实现每片 MD5 完整性校验”。可说为后续优化方案。
4. 当前项目不是后端自动在最后一片到达时合并：分片接口返回 `mergeFlag`，由前端再调用 `/api/v1/files/file/merge` 完成合并。

### 更好回答（可直接复述）

> 前端选中文件后，先使用 `Blob.slice()` 按固定大小切成多个分片，例如 4 MB；同时使用增量 MD5 计算整个文件的哈希值，作为 `identifier`。这样即使文件很大，也不需要一次性把全部内容读入内存。
>
> 上传前，前端先基于 `identifier` 发起秒传校验。如果服务端已经存在相同 MD5 的完整物理文件，就复用该文件记录，只创建当前用户与文件的关联记录，不再传输文件二进制内容。
>
> 未命中秒传时，前端先调用已上传分片查询接口，携带 `identifier`；服务端按照 `identifier + userId` 查询尚未过期的 `file_chunk` 记录并返回已上传的 `chunkNumber` 列表。前端跳过这些分片，只上传缺失部分，从而实现断点续传。
>
> 每个分片通过 `multipart/form-data` 上传，参数包括 `filename`、`identifier`、`totalChunks`、`chunkNumber`、`currentChunkSize`、`totalSize` 和分片文件流。后端把分片二进制存到临时存储目录，同时在 `file_chunk` 中记录分片编号、文件标识、用户、存储路径及过期时间。单个分片的业务定位是 `userId + identifier + chunkNumber`。
>
> 分片上传时，项目通过以 `userId + identifier` 为键的分布式锁，避免同一用户对同一文件并发写入分片状态造成冲突。后端保存分片后返回 `mergeFlag`；当前端确认所有分片上传完成后，会单独调用合并接口。服务端按 `chunkNumber` 排序读取分片并合并为完整物理文件，创建完整文件记录，再创建用户文件记录，最后删除或过期清理临时分片。
>
> 如果上传在第 8 片中断，用户刷新页面后会再次查询已上传分片，只补传缺失分片；如果所有分片已经上传但前端未发起合并，当前项目会保留临时分片直到过期。进一步可通过延迟任务扫描“分片齐全但未合并”的任务，触发幂等合并。

### 追问 1：为什么查询分片时要同时使用 `identifier` 和 `userId`？

### 更好回答

> `identifier` 用于定位同一个完整文件的上传任务，`chunkNumber` 用于定位该文件的某个具体分片。断点续传状态必须按用户隔离，因此查询条件还要加 `userId`，否则不同用户上传相同内容时，用户 A 可能看到用户 B 的分片进度。这里隔离的是临时上传状态；完整物理文件层面仍可按 MD5 去重，真正的访问权限由用户文件关系记录校验。

### 追问 2：最后一片成功但前端未调用合并，如何处理？如何避免重复合并？

### 更好回答

> 当前实现依赖前端根据 `mergeFlag` 调用合并接口，因此前端异常时会留下“分片齐全但未合并”的临时状态，最终由分片过期清理兜底。生产化优化中，我会增加延迟任务或消息补偿：扫描分片数量等于 `totalChunks` 且状态仍为上传中的任务，触发合并。
>
> 合并必须幂等：以 `userId + identifier` 作为合并锁键；进入合并后先检查完整文件记录是否已存在，存在则直接返回成功；不存在才按分片序号合并。数据库还应对完整文件标识建立唯一约束，避免分布式锁失效或重试时生成重复记录。

## 当前项目真实实现备忘

- 分片上传接口：`POST /api/v1/files/file/chunk-upload`
- 查询已上传分片：`GET /api/v1/files/file/chunk-upload`
- 合并接口：`POST /api/v1/files/file/merge`
- 分片上传锁：`FILE_CHUNK_UPLOAD`，锁键为 `userId + '-' + identifier`
- 本地启动时使用 `LocalStorageEngine` 保存分片与完整文件。
